# 01｜项目章程与 PRD

## 章程

| 项目项 | 决策 |
|---|---|
| 项目名称 | AI 智能工单与知识协同平台（A） |
| 目标 | 为小型软件团队提供工单闭环和可追溯的知识辅助，展示 AI 全栈工程能力 |
| 用户 | 请求者、支持工程师、知识库编辑者、系统管理员 |
| 交付形态 | 单组织、自托管、Docker Compose 本地演示；后续可单独部署 |
| 主技术路线 | Java 21、Spring Boot 4.1.x、Spring AI 2.0.x、Vue 3、TypeScript |
| 辅助服务 | Python 3.12、FastAPI、Docling 2.x；仅解析文档 |
| 数据 | PostgreSQL + pgvector；文件系统适配器默认保存上传文件 |
| 规模假设 | 1 个组织，20 名演示用户、1 万张工单、1 万个知识分块以内作为首轮验收样本 |

## 产品问题

工单上下文、处理过程和知识资料分散，重复问题需要人工搜索；直接让大模型“回答”又容易编造。产品将工单工作流、受权限控制的知识检索和人工确认的 AI 建议放在同一个流程里。

## 产品结果

1. 请求者可提交问题并跟踪状态。
2. 支持工程师可分派、评论、等待、解决和关闭工单，状态变化留痕。
3. 知识编辑者可上传 PDF/DOCX/Markdown 文档，查看解析失败原因并发布版本。
4. 工程师可请求分类建议、回复草稿或知识问答；答案能回链到有权限的文档片段。
5. 用户可接受/拒绝建议，评价理由进入评测样本候选，不自动成为训练数据。

## MVP 范围

- 本地用户名/密码登录、四种角色、服务目录、工单列表/详情/搜索、评论和状态流转。
- 知识空间、文件上传、解析状态、版本替换、启停和删除。
- RAG 问答、工单摘要/分类建议、回复草稿、引用展示和反馈。
- 审计日志、异步任务/Outbox、重试、健康端点、Compose、CI。

## 非目标与失败条件

- 不做多租户计费、SLA 商业化、移动端、社交协作、全功能客服 CRM。
- 不承诺无人工审核的自动处置；不自动发外部消息或关闭工单。
- 不支持开放互联网 URL 抓取、任意插件、任意工具调用或通过 LLM 执行 SQL/命令。
- 失败条件：越权知识进入回答；引用无法追溯；重复请求产生重复工单/任务；解析文件泄漏；AI 结果能绕过人工操作。

## 产品指标与拟定门槛

首轮演示用例：新用户提交、工程师接单并解决、知识编辑者发布资料、工程师得到有引用草稿并明确接受/拒绝。拟定验收目标：核心工单路径完成率 100%；无引用或权限不足时不返回受限内容；RAG 评测目标见第 10 篇。未执行的指标不报告为结果。
