# 02｜角色、用例与需求

## 角色

| 角色 | 主要权限 | 明确限制 |
|---|---|---|
| 请求者 `REQUESTER` | 创建工单；查看本人提交的工单；追加评论；确认解决或请求重开 | 不能看内部备注、他人工单或知识编辑页 |
| 支持工程师 `AGENT` | 查看被授权队列；领取/分派；内部备注；状态流转；请求 AI 建议 | 不能管理用户/角色；AI 草稿必须人工提交 |
| 知识编辑者 `KB_EDITOR` | 管理授权知识空间、上传/发布/停用文档、查看解析结果 | 不因此获得工单管理权限 |
| 管理员 `ADMIN` | 用户角色、队列/服务目录、系统配置、审计查询 | 不自动拥有下载敏感原文的理由豁免；关键操作审计 |

角色通过 `user_roles` 授予，工单另有请求人、队列和处理人范围。实施者必须将接口权限写成服务端策略。管理员可另被授予 `AGENT`，角色不隐式继承。

## 代表性用例

| ID | 用例 | 前置条件 | 验收结果 |
|---|---|---|---|
| UC-01 | 请求者提交工单 | 登录；服务目录启用 | 返回工单 ID/编号；初态 `NEW`；写入审计事件 |
| UC-02 | 工程师处理工单 | 有队列权限 | 可领取/分派、评论、转换状态；非法转换返回 409 |
| UC-03 | 请求者查看进度 | 是请求者或有队列权限 | 返回允许展示的评论和状态，不包含内部备注 |
| UC-04 | 编辑者发布文档 | 对知识空间有 `KB_EDITOR` | 上传进入解析队列；成功后新版本可检索，失败可重试 |
| UC-05 | 工程师请求回复草稿 | 可读目标工单 | 返回 202 + jobId；完成后返回草稿和引用；不会自动发送 |
| UC-06 | 用户评价建议 | 有建议读取权限 | `accepted/rejected` 与理由入库；模型调用信息保留，不记原始秘密 |
| UC-07 | 管理员停用账户 | ADMIN | 账户无法再次登录；历史审计与工单归属保留 |

## 功能需求

- `FR-01` 用户身份：登录/退出、密码哈希、停用检查、访问令牌过期和刷新策略。
- `FR-02` 工单：分页过滤、创建、详情、评论、处理人/队列、优先级、标签、状态历史。
- `FR-03` 评论：公开回复与内部备注分离；请求者端仅读公开回复。
- `FR-04` 知识：空间 ACL、原文件元数据、文档版本、解析作业、片段、发布/撤回。
- `FR-05` AI：分类/摘要/回复草稿/问答均为异步任务；带来源引用；超时/限流/失败可见。
- `FR-06` 反馈：记录接受/拒绝、反馈者和时间；人工审核后才可纳入评测集。
- `FR-07` 审计：认证失败、角色更改、下载、状态转换、发布/撤回、AI 采纳均记录操作者和对象。

## 非功能需求

- `NFR-01` 安全：默认拒绝；业务 API 服务端授权；知识检索在 SQL 层追加 ACL 过滤。
- `NFR-02` 可靠：数据库事务、Outbox 至少一次投递、消费者幂等；重试有上限和死信状态。
- `NFR-03` 可维护：模块化单体；API 有版本；迁移有前向 SQL；OpenAPI 输出。
- `NFR-04` 隐私：仅收集演示所需字段；日志对工单正文、令牌、文件内容脱敏。
- `NFR-05` 本地性：Compose 一条命令启动基础服务；CPU 即可运行。G3原生文字解析无需模型下载，后续若启用OCR/版面模型须另行提示并核验许可。
- `NFR-06` 可观测：结构化日志带 `traceId/jobId/ticketId`；AI 调用记录延迟、用量、模型名，不默认记提示全文。

## 认证会话决策

采用随机不透明 bearer session token，不使用 cookie/JWT，也不提供 refresh token。登录返回有效期 30 分钟的 token；前端只保存在内存中，页面刷新后重新登录。`POST /auth/logout` 撤销当前会话；停用用户、撤销或过期均由后端校验。数据库只保存 token 的带 pepper 哈希。API 通过同源代理或精确 CORS 白名单访问；不使用 cookie，因此没有自动携带 cookie 的 CSRF 路径，模型输出仍必须安全转义以降低 XSS 风险。
