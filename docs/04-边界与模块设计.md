# 04｜原创范围与模块边界

## 原创产品范围

本项目原创内容是工单领域模型、工单状态与队列规则、知识空间权限、Docling 解析适配器、分块/引用策略、Spring AI 服务编排、AI 建议采纳流程、Outbox 与幂等设计、界面和评测数据。Spring、Vue、Docling、PostgreSQL/pgvector 等均作为依赖使用，不复制其内部实现或品牌 UI。

## 服务边界

| 组件 | 负责 | 不负责 |
|---|---|---|
| Vue SPA | 页面、表单校验、查询状态和引用展示 | 授权判定、模型密钥、业务规则最终校验 |
| Spring Boot API | 身份/权限、工单/知识业务、事务、AI 编排、任务状态、审计 | PDF/OCR 引擎内部实现 |
| Docling FastAPI | 接收内部解析请求；安全校验后解析文件；返回 Markdown/结构化 JSON 和页码元数据 | 登录、业务数据库、embedding、检索和模型调用 |
| PostgreSQL | 业务数据、Outbox、幂等、全文检索、pgvector | 原始文件（本地文件系统适配器保存） |
| 文件存储端口 | 本地演示使用受控 `./data/uploads` 路径 | 任意路径访问或从用户 URL 下载 |

## Java 包建议

```text
com.ticknova
  identity/       # user、auth、role、policy
  catalog/        # service、queue
  ticket/         # aggregate、comment、transition、repository、api
  knowledge/      # space、document、version、chunk、acl、ingest
  ai/             # ChatClient、retrieval、prompt、suggestion、evaluation
  jobs/           # outbox、job lease、retry、idempotency
  audit/           # audit event 与查询
  shared/          # API error、clock、ids、validation
```

每個模块有自己的应用服务和仓储端口；模块间通过应用服务调用，不直接跨模块操作表。V1 不拆成多个 Java 微服务：单人项目优先保证完整闭环和易启动。

## 2026-10-24 知识协同与工作台边界

- `identity` 管理 `ADMIN/AGENT/REQUESTER/KB_EDITOR/KB_REVIEWER` 五种显式角色；`knowledge` 同时校验角色、空间读/编辑/审核 ACL 和精确版本状态。ADMIN 仅管理空间和成员；编辑者上传/撰写/提交/批准后发布，审核者只审当前精确待审版本，作者不能自审，编辑/审核 ACL 互斥。
- `/knowledge` 承载空间/分类/文档列表、初次上传和文章创建；`/knowledge/documents/:id` 承载概览、版本历史与解析结果 tabs；`/admin/knowledge-spaces` 承载 ADMIN 创建空间与成员管理；`/knowledge/reviews` 承载 KB_REVIEWER 待办。旧 `/knowledge?documentId=...` 转到独立详情并保留版本/片段等定位参数。
- `DocumentActionBar` 复用服务端文档级及版本级 `allowedActions`；版本动作绑定明确版本 ID。`ArticleEditorView` 继续负责草稿自动保存与提交，动作不能跨越后端授权边界。
- `workspace` 返回 ACL 过滤后的真实门户摘要/发布时间/分类数量，以及仅 ADMIN 可读的计数分析。前端分析的 7/14/30 天选项转换为原有 UTC 日期 API，ECharts 懒加载并保留 HTML 每日数据表。

## 适配端口

- `DocumentParserPort` → HTTP `DoclingAdapter`。
- `ChatModelPort/EmbeddingPort` → Spring AI provider adapter；本地 mock adapter 用于无密钥演示。
- `FileStoragePort` → `LocalFileStorage`；生产替换对象存储需要实现同一端口。
- `Clock/IdempotencyStore/OutboxPublisher` → 可注入测试替身或数据库实现。
