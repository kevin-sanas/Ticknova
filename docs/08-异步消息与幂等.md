# 08｜异步任务、消息与幂等

## G5 失败索引恢复补充（2026-10-23）

失败索引现在有独立的手动重试入口。只有当前仍有空间编辑权的用户可操作解析 `READY` 且索引 `FAILED` 的版本；条件更新把索引状态置为 `PENDING`、清除旧 profile/租约/错误并重置尝试数，同一事务写审计。重复点击或状态已变化返回 409，不创建新文档版本，也不改动既有解析 job。新模型 profile 的自动重建逻辑保持独立；后台继续按原租约与有限重试领取任务。页面仅根据服务端 `canRetryIndex` 展示操作。

## Ticknova V2 补充

AI用户中止调用服务器cancel接口，先锁Outbox事件再锁job，与领取/成功/失败路径保持一致；原子设置CANCELLED、事件已投递并清空租约。较晚返回的模型结果或异常不能写成功、重试、失败或相关审计。已完成任务返回409，重复中止204；仍复查创建者及原请求范围。前端收到成功后才显示已中止，失败保留真实任务状态。

文章生成版本继续复用私有上传/Docling任务及24小时幂等记录；历史源复用与旧key重放不同：新提交可恢复历史快照为当前可审核版本，旧key重放只返回原结果，不改变随后产生的latest。版本/发布/审核及审计同事务，CAS冲突不覆盖原草稿。

## 首版方案

G4 实际补充：AI_REQUEST 使用独立 worker，120 秒租约与 fencing、最多五次尝试、最多两个并发模型调用；调用不占数据库事务。索引器按文档版本和 profile 分批领取，每次最多 32 段/64,000 字符，保存进度直到所有分块就绪。切换 profile 后旧向量不参与检索。查询/反馈一致性事务遇 SQLSTATE 40001 最多开启三次全新的 REPEATABLE READ 事务，耗尽返回稳定 409；撤权隐藏审计先提交，再返回 404。G4 当时尚无失败索引专用重试入口；当前实现见上方 G5 补充。

首版不引入消息代理；PostgreSQL 同时保存业务事务和 Outbox。提交工单可同步返回；文件解析、embedding、RAG 和 AI 建议写入 `ai_job`/任务记录并返回 202。事件写入 Outbox 与业务数据处于同一事务，worker 用短事务领取租约后在事务外调用 Docling/模型。

## 投递流程

1. 业务事务插入 `ai_job` 与 `outbox_event(PENDING)`，提交后立即返回 job ID。
2. Worker 执行 `SELECT ... FOR UPDATE SKIP LOCKED` 领取到期事件，写 `locked_until` 并增加 `attempts`。
3. 在事务外调用内部服务或 AI provider；外部调用都带稳定的 `jobId` 作为幂等引用。
4. 成功后同事务写结果、`COMPLETED` 和 Outbox `DELIVERED`；重复事件命中唯一约束并安全返回既有结果。
5. 可重试故障采用指数退避（建议 2s、10s、60s、5m，随机抖动）；达到 5 次后 `DEAD`，显示可审计的失败码并由人工重试。

## 幂等键

| 操作 | 键/唯一约束 | 重放行为 |
|---|---|---|
| 创建工单等写 API | `api_idempotency(user_id, operation, idempotency_key)` + 请求 SHA-256 摘要 | 同摘要返回同资源 ID/状态码并重新鉴权；不同摘要返回 409；进行中返回 409 + 可重试提示 |
| 上传文档版本 | `(documentId, sha256)` | 同文件返回既有版本/任务，不创建重复解析 |
| AI 请求 | `ai_job.idempotency_key`：用户、类型、对象、内容版本的摘要 | 已完成复用结果；进行中返回同一 job |
| 分块写入 | `(documentVersionId, chunkIndex)` | upsert 或事务整体回滚后重试 |
| 状态转换 | `ticket.version` 与状态历史唯一请求 ID | 并发重复不可创建第二次转换 |

`api_idempotency` 仅保存创建结果的资源 ID 和 2xx 状态码，不缓存请求/响应正文；键保留 24 小时。领取键与业务写入在同一事务提交；事务回滚时键也回滚。清理只删除已过期记录。

## 故障处理与运行

G3 实现采用120秒租约和随机 `lease_token` fencing；HTTP 客户端整体95秒上限，服务内部90秒硬终止。每次完成/失败写入先验证当前租约，过期 worker 不覆盖新 worker。解析在事务外，分块、READY、任务完成、Outbox投递与审计在一个事务中提交。指数退避为2s/10s/60s/5m加抖动，最多5次；人工重试创建新 job，不改写旧 FAILED 记录。空间写操作统一先锁空间、再锁文档；首次上传锁后单独重新读取 ACL，避免锁等待期间沿用旧权限快照。

Micrometer 注册 `ticknova.knowledge.outbox.pending/processing/dead/retries/oldest_pending_seconds` 和 `ticknova.knowledge.ingest.stage{stage,outcome}`。不含正文/文档名标签；数据库不可读时 gauge 为 NaN。当前 HTTP 运维暴露仍只有 health，未交付指标抓取端点或告警系统。

- 模型超时与限流可重试；权限拒绝、格式不支持、维度不匹配为不可重试错误。
- Docling 解析任务可安全重启；先写临时结果，完整校验后原子标记就绪；失败版本不影响上一个发布版本。
- worker 暂停时 Outbox 保留；数据库连接恢复后继续；租约超时可被另一 worker 接管。
- `DEAD` 事件要展示 `jobId`、阶段和脱敏错误码。重试需创建 audit event，不修改历史失败证据。
- 指标：pending 数量、最老事件年龄、重试数、dead 数、任务各阶段时长。不得把完整正文写进指标标签。
