# 09｜安全、隐私与权限

## Ticknova V2 权限补充

空间内容写保留显式ADMIN或KB_EDITOR角色谓词，并同时要求当前canRead/canEdit；ADMIN无正文读取绕过。独立审核额外要求当前有效KB_EDITOR、空间canEdit且非版本作者。等待角色/空间锁之后重新读取权限，角色撤销和停用立即影响后续写操作。

门户、正文/快照、浏览计数及AI召回/引用都要求当前READY、APPROVED发布与空间ACL；普通读者不接收草稿标题/历史版本。成员管理权和内容读取权独立，“仅空间配置”仍可管理成员但不查询分类或正文。前端收到权威401/403/404后清空相关缓存、分类表单和旧请求，精确引用不可用时不回退其他版本。

RichDoc为闭合安全结构，不保存可执行HTML或任意资源嵌入。显式退出先确认未保存内容；过期/401仍立即清理，旧会话的延迟响应不能覆盖新会话。供应链实测及未解决的Pillow/Docling版本约束见第15篇，不能沿用历史零命中结论。

## 授权模型

默认拒绝；接口层完成身份验证，应用服务按对象再次鉴权，数据查询本身也带授权范围。角色不做隐式继承。工程师须在 `queue_member` 中被授予处理队列；知识 ACL 在向量/全文召回 SQL 执行前应用，不允许“先全局搜索，再在结果中隐藏”。请求者永远不能读取 `INTERNAL_NOTE`。

| 资源/动作 | REQUESTER | AGENT | KB_EDITOR | ADMIN |
|---|---|---|---|---|
| 本人工单读/建/公开评论 | 是 | 是 | 否 | ADMIN单独不具备；另有REQUESTER/AGENT时按显式角色 |
| 队列工单处理/内部备注 | 否 | `queue_member` 授权队列 | 否 | 另具AGENT及队列处理权才可操作 |
| 知识空间读取 | 按成员 `can_read` | 按成员 | 按成员 | 按成员；不绕过撤回状态 |
| 知识文档编辑 | 否 | 否 | 授权空间 `can_edit` | 授权空间 `can_edit` |
| 角色/服务配置 | 否 | 否 | 否 | 是 |

## 威胁与控制

G4补充：候选SQL先过滤当前用户/空间ACL、当前发布指针及同profile索引；任务提交时固定有效空间集合，worker提交前与模型完成后再次检查。已生成结果的每次读取与反馈都复核原范围和全部引用，任一失效则不展示整份结果并记录安全审计。后台任务创建者被停用或要求改密时不继续生成。AI工单输入限公开正文/公开回复；采纳仅编辑本地草稿，不自动发送、改状态、分派或保存字段。

默认mock不出网，使用确定性提取与哈希特征，不宣称语义模型效果。真实模式只读取项目显式AI环境配置，不自动获取宿主密钥；界面显示第三方处理提示，用户问题、公开工单与授权片段可能发送到所配置服务。模型无工具，业务文本作为JSON数据而非系统指令，返回引用ID必须为本次召回的子集，服务项必须属于有效目录。

- **提示注入/恶意资料**：把文档和工单视作不可信数据；system prompt 说明不可执行资料内指令；限制检索来源；模型没有任意工具。
- **越权 RAG**：在 SQL 中联结 `knowledge_space_member`/`can_read` 和 `PUBLISHED`；每个答案存 citation document/version/chunk；撤回后再次校验。
- **上传攻击**：文件名只用于展示，落盘 key 为随机 UUID；路径不可由用户控制；大小/格式/MIME/页数校验；解析容器非 root、只读根文件系统、限 CPU/内存/时间。
- **SSRF**：解析 API 仅接收服务端存储文件 ID 或内部传输内容，不接受 arbitrary URL；关闭 Docling URL 输入路径。
- **凭据/令牌泄漏**：密钥只来自环境变量/secret store；禁止写到 `application.yml`、日志、提示词、截图或仓库；定期轮换。
- **跨站/会话**：使用不透明 bearer token，不使用 cookie；前端内存存储避免长期 token 持久化；API 同源代理/精确 CORS 白名单；登录速率限制。
- **审计**：角色变更、下载、发布/撤回、状态转换、反馈采纳记录 actor/time/object/traceId；不记录密码、access token、原始 prompt。

## 数据处理

采用不透明 bearer session token，随机生成后只存带 pepper 的摘要；期限 30 分钟，不提供 refresh token。Vue 仅在内存保存 token，过期后重新登录；登出调用 API 撤销 session。API 用同源代理或精确 CORS 白名单，不使用 cookie；所有模型输出和用户 Markdown 安全转义。只保存演示所需用户名、角色、工单文本、知识文档和结果。原始上传、提取文本、AI job、审计的保留期通过配置表达；建议演示环境 30/90/180 天分层保留并允许管理员清理。清理任务先撤回文档，再删 chunks/文件；所有删除有结果和审计。真实模型 API 可能将输入送至第三方，真实 provider 模式必须在 UI/README 标注并需用户自行确认供应商的数据处理条款。

## 安全验收

必须包含 REQUESTER 读他人工单/内部评论、无 ACL 知识召回、撤回文档引用、超大/伪造文件类型、模型返回伪造引用、提示注入文档等负向用例；任一越权泄露即阻断发布。
