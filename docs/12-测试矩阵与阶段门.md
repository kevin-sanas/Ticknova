# 12｜测试矩阵与阶段门

本页说明项目的验证范围、复现入口及已记录结果。测试结果仅适用于对应代码、环境和数据集；GitHub Actions 的当前状态以工作流运行记录为准。

## 测试范围

| 范围 | 主要检查 |
|---|---|
| 身份与权限 | 登录、首次改密、会话失效、角色和队列权限、知识空间 ACL，以及停用或撤权后的访问限制 |
| 工单 | 创建、领取与分派、公开回复和内部备注隔离、状态流转、版本冲突与幂等 |
| 知识 | Markdown、TXT、PDF、DOCX 上传与解析；审核、发布、版本更替、撤回、归档及失败重试 |
| AI 与检索 | 空间权限过滤、引用来源、无证据拒答、任务取消，以及人工采纳后仍需手动执行 |
| 前端 | 类型检查、Lint、组件状态、表单和页面交互，以及构建 |
| 运维 | 数据库迁移、隔离测试、服务健康检查和备份恢复演练 |

## 运行测试

在具备 Docker 和 Docker Compose 的环境中，项目根目录的 PowerShell 入口可运行后端 PostgreSQL 集成测试：

```powershell
.\scripts\Test-Backend.ps1
```

该脚本使用项目专用测试配置和 `ticknova_test` 数据库，并使用 Maven 缓存卷；运行前确认测试项目名、配置和相关容器不会与已有资源冲突。它不会自动清理所有测试服务，使用后应按实际容器检查。不要将集成测试连接到业务数据库。

前端检查在 `frontend` 目录执行：

```sh
npm ci --ignore-scripts
npm run typecheck
npm run lint
npm test
npm run build
```

解析服务在 `docling-service` 目录执行：

```sh
uv sync --frozen
uv run --frozen pytest -q
```

项目根目录的脚本契约测试为 `node --test scripts/*.test.mjs`。PowerShell 浏览器测试入口为 `scripts/Test-Browser.ps1`；脚本使用固定的 `ticknova-browser` 测试项目，并会重置对应测试配置和容器及数据卷。运行前应检查该项目没有需要保留的数据，测试材料应使用原创内容。各脚本与环境准备步骤参见[部署与运维](11-本地部署运维与CI-CD.md)。

## 未完成的验收

人工标注的 groundedness 与完整真实模型质量门、生产环境部署、跨机灾备目标和长期稳定性没有因上述测试通过而完成。容器 OS 漏洞扫描及其他浏览器、原生 Linux/macOS 端到端验证应按实际运行情况单独记录。性能目标与实测结果必须分开；没有运行的检查应标注为未运行。
