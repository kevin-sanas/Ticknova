# 13｜功能范围与发布交付

Ticknova 面向单组织、本地部署的服务台场景，功能、接口与数据模型以源码、数据库迁移及对应契约为准。本页是发布检查清单，不代表项目已经完成生产发布验收。

## 已实现的主要能力

- **身份和服务请求**：显式角色、会话认证、队列与服务目录、工单状态流转、公开回复与内部备注隔离，以及并发版本和幂等处理。
- **知识协作**：按空间授权访问，上传或撰写文档，解析并保存版本；独立审核者审核，编辑者在通过后发布。作者不能审核自己的版本，管理员也需要空间权限才能读取正文。
- **知识检索与 AI 辅助**：在可访问的已发布知识范围内检索并关联来源；AI 可生成回答、工单摘要和回复建议，实际发送或保存由用户确认。
- **运营与维护**：管理页面、审计查询、运营分析、数据库迁移、备份恢复脚本和隔离测试入口。

角色职责和约束详见[角色与用例](02-角色用例与需求.md)、[API 契约](07-API契约.md)和[安全与权限](09-安全隐私与权限.md)。

## 发布检查清单

### 安装与数据

- [ ] 根据 [README](../README.md) 和[部署与运维](11-本地部署运维与CI-CD.md)核对环境要求、配置、镜像来源及启动步骤。
- [ ] 准备独立的业务配置，确保密钥不进入版本库、日志或演示材料；确认网络暴露范围和账户管理方式。
- [ ] 在独立环境验证空库及目标旧版本到当前版本的迁移；保留可恢复的数据库和上传原件备份，并实际抽检恢复结果。
- [ ] 演示和测试使用原创或许可允许的数据，不包含真实用户隐私或敏感文件。

### 功能与安全

- [ ] 运行[测试矩阵](12-测试矩阵与阶段门.md)中与变更相关的自动化测试和浏览器关键流程。
- [ ] 核对角色和对象权限、知识空间 ACL、独立审核、撤权、会话失效与内部备注隔离。
- [ ] 验证工单版本冲突、幂等操作、上传大小与格式限制、解析失败恢复和知识撤回行为。
- [ ] 核对 AI 引用对应真实可访问的来源；确认无证据时明确拒答，建议采纳后仍需人工执行。
- [ ] 涉及共享前端组件时，检查关联页面、弹窗和下拉菜单的加载、错误、焦点、键盘及响应式状态。

### 依赖、评测与发布说明

- [ ] 根据锁文件和镜像版本复核依赖、许可证与安全公告，并在适用时扫描容器操作系统依赖；现有扫描报告仅覆盖其记录的时间和范围。
- [ ] RAG 与性能指标注明数据集、模型、环境、样本量及测量方法；mock 与真实模型结果分开，未测项目不填为通过。
- [ ] 在发布说明中列出已知限制、备份恢复方法和不适用范围；确认 CI 对应实际发布提交。

## 尚需单独验收

真实模型回答的人工 groundedness 和完整质量门、生产环境部署、跨机灾备目标、长期稳定性及运行环境的安全审计，均需要按目标部署环境分别验证。历史测试和本地演示不构成这些项目的通过证明。

已记录的回归、性能和 RAG 证据及其限制见[测试矩阵与阶段门](12-测试矩阵与阶段门.md)和[RAG 设计与评测](10-RAG设计与评测.md)；供应链范围见[许可证与依赖边界](15-开源许可证与接口边界.md)。
