## 发布清单

- [ ] `README` 标注 docs 与源码的区别、启动前提、seed 用户和重置方式。
- [ ] `.env.example` 无真实密钥；`.gitignore` 覆盖 `.env`、上传、数据库卷、模型缓存。
- [ ] Flyway 从空库/上个版本均可迁移；备份恢复后抽检文件 hash。
- [ ] 依赖锁文件、许可证/SBOM、镜像版本和来源固定；无 `latest` 标签。
- [ ] 角色越权、Prompt injection、文档撤回、Outbox 重复/崩溃检查通过。
- [ ] RAG 报告标注数据集规模、模型、配置和限制；未测目标保持未测。
- [ ] 演示数据使用虚构内容，不放真实用户/公司数据或敏感文件。
- [ ] 发布说明列出已知问题、恢复办法和不适用范围。

## 2026-10-21 Ticknova V2 全量整改实施计划（本地功能与UI验收通过）

用户明确要求依据UI设计规范及执行指南整改，并选择同时开发缺少的业务功能；新文档版本须由另一位有空间编辑权限的知识编辑者审核后发布，保留当前已发布内容。范围包括全局Tokens/共享组件/所有现有页面、员工门户、知识分类与富文本自动保存、独立审核、运营分析及AI用户中止。默认浅色主题，界面、工程和数据库名称统一为Ticknova。

实际结果：后端201项、前端164项、完整浏览器35项及知识视觉3项通过；五宽度、相关弹窗/抽屉/确认浮层与键盘焦点已验证，主页面及代表性局部截图已人工检查。V4→V6增量升级保留现有用户/密码/数据。限定范围源码评审及后续交互/CSS修复复核通过，详细证据见第12/16篇。**整体供应链与生产发布未通过**：Pillow公告兼容修复、G5运维和真实模型/性能仍单独待办，不将UI验收替代发布门。

分阶段：①影响分析与接口契约；②V5知识创作/分类/审核与V6门户/浏览统计/分析/AI取消；③Tokens及共享组件、三栏工单/Inbox/门户/编辑阅读及管理页；④授权/并发/旧发布回归、全套测试、五种宽度和弹层键盘浏览器验收、依赖与凭据检查。每个实现范围独立评审，最后整合复核。

API设计：知识分类树按空间隔离；富文本以受限结构化JSON保存草稿并乐观锁自动保存，提交版本复用私有Markdown与Docling摄取；审核与发布分离，新版本缺审核不可发布，管理员无空间内容绕过。门户检索在权限和当前发布过滤后返回结果，热门依据真实每日浏览；运营统计仅管理员可读、明确UTC日期区间和单位。AI中止在服务器取消任务并撤销租约，不能只停止界面轮询。固定接口、执行记录与裁决已归档至 `evidence/ui-v2-review.json`，实际命令摘要见 `ui-v2-test-runs.json`；临时目录在归档后清理，不新增交接MD。
