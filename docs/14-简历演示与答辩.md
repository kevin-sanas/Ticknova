# 14｜简历、演示与答辩

## 简历描述模板

> 独立设计并实现 AI 智能工单与知识协同平台：以 Spring Boot/Spring AI 构建工单和 RAG 业务，以 Vue 3 实现工作台，使用 FastAPI/Docling 解析 PDF/DOCX；通过 PostgreSQL Outbox、幂等键和权限过滤处理异步摄取与知识检索。RAG 指标为【填写实际数据集、模型、实测值】；当前演示范围为单组织本地部署。

方括号字段必须替换为真实测量，未做的内容删去，禁止把本工程文档写成已上线项目。

## 5 分钟演示

1. 登录 REQUESTER，创建含非敏感虚构信息的工单。
2. 登录 AGENT，查看队列、领取工单、留内部备注并验证请求者不可见。
3. ADMIN 在独立空间管理页创建空间、配置成员；KB_EDITOR 以空间读/编辑权限上传自制手册或撰写富文本文章，展示分类、自动保存和解析进度并提交。KB_REVIEWER 以读/审核权限从审核待办打开当前精确待审版本，通过或带理由退回；批准后由 KB_EDITOR 发布。作者不能自审，编辑/审核 ACL 互斥，ADMIN 不隐含正文权限，旧发布在新稿期间保留。
4. 在工程师界面请求回复草稿，展示文档名、版本、页码、片段，拒绝或采纳草稿。
5. 使用本地 mock，演示真实中止生成、无证据拒答，以及普通工单功能；从员工门户核对真实发布时间、分类数量与知识卡片，跳到独立文档详情及精确引用。请求者展示“我的工单”，工程师展示“可访问工单”；管理员切换运营分析的7/14/30天、核对每日图和HTML表格及审计。完成占比与AI采纳率按页面实际口径解释，采纳率不当作准确率。真实模型故障、质量和性能不得以本地 mock 演示代替验收。

## 2026-10-24 演示准备边界

新空库包含 admin/agent/requester/editor/reviewer 五账号，密码只读本机私有配置，不进入演示录屏或文档。既有非空库不会自动按用户名改为审核角色，演示前须通过管理员受控配置确认显式角色与互斥 ACL，保留历史和密码。按第12篇实际结果说明本轮验证；新增图表依赖不表示外部审计已经通过。

## 面试深挖题

- 为什么 Spring Boot 做主后端、Docling 单独 Python？——业务事务与权限统一；文档解析依赖/模型隔离。
- Outbox 如何避免数据库成功但消息丢失？——同一事务写业务和事件；worker 至少一次投递，消费者幂等。
- RAG 如何避免 ACL 之后过滤导致泄露？——ACL 在召回 SQL 中；对最终 citation 再校验；撤回状态参与过滤。
- 如何避免模型编造出处？——生成只引用召回 ID，服务端校验子集；无有效引用拒答；引用可回源。
- 为什么不微服务？——一个学生项目先完成闭环；模块接口和适配端口减少未来拆分成本。
- 性能指标怎样证明？——给测试环境、数据规模、并发、测量工具和结果；拟定目标与测量结果明确分开。
